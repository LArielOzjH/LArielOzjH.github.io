Evaluation runs produce numbers that look precise, but the measurement path often contains enough orchestration noise to hide the real system behavior.

## Ledger format

I want each run to keep separate rows for model execution, host-side scheduling, queueing, data loading, and scoring.

### Why it helps

If latency improves, the ledger says where it improved. If quality changes, the ledger keeps the measurement protocol close enough to audit.
